# 真实性、数据与角色规则

本文件提供措辞判断规则；结构化字段、枚举和校验门禁以 [claim-ledger-schema.md](claim-ledger-schema.md) 为准。

## 事实台账

每个可见断言应记录：`claim`、`source`、`verification`、`scope`、`time_window`。其中：

- `source_grounded`：用户提供的简历、材料或公开一手来源明确支持。
- `user_attested`：用户本人确认，但未有可公开材料。
- `unknown`：未确认；不得作为成果、数字或角色写入简历。

## 角色强度

| 证据 | 可用表述 | 不可升级为 |
| --- | --- | --- |
| 接收任务并执行 | 执行、完成、支持某模块 | 负责人、主导 |
| 明确负责一个模块 | 负责/推动某模块设计与落地 | 整体项目 Owner |
| 发现问题、提出方案并推动闭环 | 主导该限定项目/模块；模块 Owner | 无边界的全局 Owner |
| 规划或方案尚未实施 | 规划、设计、提出 | 已上线、取得结果 |

## 数据与语言

- 不编造百分比、规模、效率、满意度或转化率；不把不同口径相加。
- 每个数字尽可能附带时间范围、基线或统计来源；无法说明时删掉或标为待确认。
- 团队数据需写出个人承担的具体环节，不能暗示独占成果。
- 没有数值时，用真实交付物、覆盖对象、采纳状态、流程变化或复盘洞见替代。

## 高风险词

`Owner`、`从 0 到 1`、`主导`、`搭建体系`、`上线`、`增长 X%`、`覆盖 X 用户` 均需有明确证据与范围。学校 Title、公司性质、奖项、开源角色、Offer 与薪资同样不得猜测或补写。
