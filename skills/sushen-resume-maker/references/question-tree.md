# 能力深挖问题树

深挖的目标不是证明候选人“是不是 Owner”，而是把“做过什么”继续挖成“解决了什么难题、如何思考、怎样推动、留下什么、证明了什么能力”。每轮只问 1–3 个最可能产出新简历亮点的问题；已经从材料或上一轮回答得到的信息不再重复问。

## 0. 输入与定位

- 读取完整原始简历、补充经历和目标 JD。
- 先提取已写出的事实，再标出可能被低估的线索：数据、流程、协作、内容、产品、用户、工具、跨市场、交付物。
- 判断目标岗位最重视的 3–5 项能力，但不能为了匹配 JD 诱导用户编案例。
- 问题必须引用用户的实际经历或上一轮回答；没有线索时才使用通用问题。

## 1. 第一轮：发现潜在线索

优先从下列维度选择三个不同问题：

### 复杂问题

- 这段经历里最难、最模糊或最需要动脑的一件事是什么？难点来自人、流程、数据、资源还是时间？
- 你如何把问题拆开、确定优先级并推进到可执行？

### 主动发现

- 哪件事不是别人明确交代，而是你自己发现问题、提出改进并推动发生？
- 你最初看到了什么异常、反馈或机会信号？

### 判断与取舍

- 哪个动作不是照着执行，而是你比较方案后做出的选择？
- 当时有哪些约束、备选方案和取舍依据？

### 经历特定问题

- 数据/后台：你看到了什么，原先判断是什么，你据此改变了哪个动作？
- SOP/流程：旧流程哪里最乱或最容易出错，你设计了哪些关键节点，后来谁在用？
- 供应商/跨团队：最难协调的需求或冲突是什么，你如何分类、统一标准并推动行动？
- 内容/直播：你如何判断受众、卖点和节奏，哪次根据表现或反馈调整了方案？
- 电商/独立站：流量到成交的链路里卡点在哪里，你做了什么页面、内容或运营调整？
- 产品/AI/工具：解决谁的什么问题，你如何测试、收集反馈并决定迭代？

## 2. 第二轮：把经历挖成能力

第二轮必须根据第一轮回答追问，不能机械换一组通用题。

### 分析到决策

- 哪个数据或反馈改变了原来的判断？
- 你据此采取了什么动作，如何验证方向是否有效？

### 推动与影响

- 对方为什么最初不配合或意见不一致？
- 你用了什么信息、规则、沟通方式或小范围验证让事情继续向前？

### 方法与体系化

- 做过几次后，你总结出了什么模板、检查清单、框架或 SOP？
- 相比最初做法，它减少了什么重复工作、错误或沟通成本？

### 用户与业务理解

- 你如何区分表面需求和真实问题？
- 这个判断怎样改变了方案、优先级或交付形式？

### 快速学习

- 为完成任务，你最快补上的知识或工具是什么？
- 你如何学习，并用真实任务验证自己已经掌握？

## 3. 第三轮：转成有竞争力的简历素材

### 结果与影响

- 如果没有增长数字，还有什么真实结果：覆盖范围、采用情况、交付速度、错误减少、协作效率、用户反馈或复用次数？
- 哪个前后变化最能说明这件事有价值？

### 可复用资产

- 最后留下了哪些别人可以继续使用的 SOP、分析框架、模板、脚本、内容方法或项目机制？
- 它被哪些人、哪些场景或后续项目持续使用？

### 核心竞争力

- 如果面试官只能记住这段经历的一点，你希望是哪项能力？
- 用一个具体事实证明它，不要只说“沟通能力强”“学习能力强”。

### JD 遗漏证明

- 对高权重但仍缺证据的 JD 要求，询问是否有原简历漏写的真实小案例。
- 用户没有案例时直接跳过，不得要求其描述“如果遇到会怎么做”并把答案写成经历。

## 4. 回答转 Claim

每个具体、非假设的回答都应新增一条 `origin=interview` Claim，而不是只附在旧 Claim 的备注里。

- 保留用户原话，记录问题轮次和能力维度。
- 去除完全重复回答。
- 将新 Claim 与相关原始事实组合，形成“场景/难点＋个人动作/方法＋结果/影响”的 bullet 候选。
- 暂无量化数据时可以使用具体的定性影响，不能虚构数字。
- 假设性回答、计划做法和“我应该会”不得作为已发生事实。

## 5. 最终准确性校对

准确性校对只针对已经准备进入简历的候选亮点：

- 含 Owner、主导、0→1 等强角色词时，确认限定模块和真实贡献。
- 含增长、提升、降低等指标时，确认口径、时间窗、数据来源和可合理归因范围。
- 含上线、落地、完成时，确认真实项目状态。
- 涉及团队成果时，保留团队语境并写清个人动作。

每条亮点最多追加一个必要的边界问题。不得连续围绕“最终决策权是谁”“能否归因于你”进行审讯式追问。不能确认时降低措辞或不采用，不影响继续挖掘其他能力。

## 问题质量门禁

一个问题只有同时满足以下条件才可被提出：

1. 能引用当前经历、JD 或上一轮回答中的具体线索；
2. 答案有机会增加新的能力证据、方法细节或结果信息；
3. 尚未被材料回答；
4. 不诱导用户虚构数字、职责或案例；
5. 与本轮其他问题属于不同能力维度。

若问题只会再次确认 Owner、边界或真实性，而不能带来新的简历信息，应放到最终校对阶段，不能进入前三轮能力深挖。
