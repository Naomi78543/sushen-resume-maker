# 深度拷打问题树

每轮只问 1–3 个最能降低不确定性的问题；已从材料得出的答案不再问。

## 0. 定位

- 目标岗位、行业和投递场景是什么？
- 希望招聘方首先记住哪三项能力？
- 有哪些经历必须保留、必须匿名或不能披露？

## 1. 背景与对象

- 这项工作为什么存在？原先的痛点或目标是什么？
- 服务对象是谁（用户、商家、内部团队或业务线）？
- 不做会带来什么影响？依据来自数据、反馈、业务需求还是调研？

## 2. 个人边界

- 将项目拆成模块后，你亲自负责哪些模块？谁做决策、谁协同？
- 你提出过什么方案或优化？它为何可行？
- 你协调了哪些资源、推进了哪些节点？

## 3. 方法与产出

- 具体做了哪些分析、设计、实验、开发或流程建设？
- 留下了什么可复用产物（PRD、原型、内容体系、工具、流程、模块、文档）？
- 如何验证产物已被采用或达成目标？

## 4. 结果与证据

- 数据口径、时间窗、基线和统计方式是什么？
- 没有指标时，是否有覆盖用户/团队、采用次数、交付状态、周期缩短或质量改善？
- 结果中哪些是团队结果，哪些部分可合理归因于个人？

## 5. 压力测试

- “你具体负责到什么程度？”
- “这个结果为什么能归因于你？”
- “若重新做一次，你会如何优化？”

若不能回答，降级措辞或将其列入待补证据，不能用强角色词掩盖。
